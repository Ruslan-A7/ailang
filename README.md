# AILang

**Українська** · [English](README.en.md)

Від авторської ідеї — до програмного забезпечення зі збереженням її змісту.

![AILang — міст між людською мовою та програмним кодом](.Результат/Медіа/ailang-banner-neural.png)

**Поточна версія: 0.6.3 · українська робоча редакція · до першого стабільного випуску.**

AILang — набір інструкцій, специфікацій і правил, які допомагають ШІ-агентам правильно сприймати опис програмного забезпечення природною мовою та реалізовувати задум автора на відповідному технологічному стеку.

Саме програмне забезпечення автор описує у `.Джерело` (англійська назва ролі — `.Source`). AILang пояснює агенту, як читати цей опис, уточнювати неоднозначності, працювати з вимогами, налаштуваннями й дозволами та перевіряти відповідність результату. Результати різних агентів можуть відрізнятися; головне — максимально точне збереження суті авторського задуму.

## Що дає AILang

- Опис бажаної поведінки природною мовою в Markdown.
- Відокремлення авторських джерел, результату, документації та інструментів.
- Явні вимоги, стабільні ID та зв’язок «джерело → результат → перевірка».
- Налаштування мови, технологій, авторства, Git та дозволів для кожного проєкту.
- Повторний перегляд налаштувань після їх зміни й погодження потрібної міграції.
- Правила безпеки, приватності, роботи з залежностями й збереження контексту.

## Почати використовувати

1. Скопіюйте **вміст** `.Результат/uk` у папку `.AILang` вашого проєкту. Папку `uk` усередині `.AILang` не створюйте.
2. У кореневому `AGENTS.md` додайте посилання на `.AILang/Інструкції/Agents.md` і доручення прочитати його перед роботою.
3. Перегляньте шаблони налаштувань у пакеті: задайте мови, стек, авторство, ліцензію, дозволи та Git-політику свого проєкту.
4. Опишіть програмне забезпечення в папці джерела, назву якої визначають ваші мовні налаштування.
5. Доручіть агенту прочитати AILang, налаштування та джерело. Початкова ініціалізація структури дозволена як явний виняток правил; подальші зміни захищених авторських матеріалів потребують відповідного дозволу.

Наприклад, авторський Markdown-опис може починатися так:

```markdown
# Особистий список справ

Ідея: допомогти користувачу планувати день.

- **TASK-01: користувач може додати справу з назвою.**
- **TASK-02: виконані справи можна приховати окремим перемикачем.**
- Критерій TASK-01: після підтвердження нова справа з’являється у списку.
```

Це приклад опису вимог. Конкретний код, формати файлів і перевірки агент обирає відповідно до погодженого стеку та налаштувань. Значення автора й ліцензії цього репозиторію не переносяться автоматично на ваш продукт.

| `.Ідея` | Початкові авторські матеріали |

| `.Результат/uk` | Поточний український пакет інструкцій |
| `.Результат/Медіа` | Логотип і заставка |
| `.Налаштування` | Параметри цього проєкту |

Ми розробляємо саму AILang, тому кореневої `.AILang` тут немає. У проєктах користувачів ця папка містить одну обрану локалізацію. Інші переклади заплановані після завершення першої української версії.

## Планувальник Codex для Windows

Запуск: [Показати таймери.cmd](.Інструменти/Автоматизація/Показати%20таймери.cmd). Потрібні Windows PowerShell 5.1 із WPF та встановлений і авторизований Codex CLI із підтримкою `queue` й app-server.

Планувальник має ручний таймер, цикл **05:05**, власні тексти, історію запитів, кнопку **«Надіслати зараз»**, читання квот та журнал рішень. UUID зберігається між запусками; поруч відображається назва чату, якщо Codex її надає. За потреби шлях до CLI можна вибрати кнопкою **Codex.exe…**.

Надсилання починається лише після відповідної дії користувача. Кнопка негайного надсилання використовує ручні схвалення. Невідомі квоти блокують доставку; низькі квоти застосовують установлені пороги. Прийняття `queue` означає прийняття запиту, а не завершення роботи агента.

UUID, назва чату, історія й журнал зберігаються лише в локальній ігнорованій Git папці `.Стан`. Не вводьте секрети в тексти запитів.
