# Автоматизація AILang для Windows

Ідея: надати окремий приклад планувальника з достовірними квотами та явним вибором сеансу.

Версія: 0.4.0. Це адаптований приклад AILang на основі дослідженого механізму queue. Повний авторський комплект з [інструкцією перенесення](<../.Ідея/Приклади/Автоматизація роботи/README.md>) міститься безпосередньо в .Ідея/Приклади/Автоматизація роботи; вміст його файлів не редагується.

## Що містили авторські приклади

Початкові три файли не називали відправника. Після отримання повного комплекту автор прямо доручив видалити «Не повні» й підняти вміст «Повні робочі інструменти» на рівень вище; це виконано разом із прихованими файлами. У повному комплекті відправник — deferred-resume.ps1: після відліку виконує codex queue. deferred-launch.ps1 запускає його через Task Scheduler; deferred-first.ps1/deferred-cycle.ps1 задають одноразовий/повторний режим. shutdown-after-work.ps1 — окреме вимкнення. Архів reference збережений без редагування, його .gitattributes зберігає початкові байти.

## Новий приклад

- [Планувальник.ps1](../.Інструменти/Автоматизація/Планувальник.ps1) — WPF-вікно, таймер, ручний інтервал, перемикач надсилання та повтору, запит, історія, квоти й очікування їх відновлення.
- [Сховище.psm1](../.Інструменти/Автоматизація/Сховище.psm1) — локальна історія в .Стан/Автоматизація/Історія.json: усі надіслані запити й останні 300 чернеток/спроб. Чернетка зберігається після двох секунд без змін, також кнопкою; спроба й прийняття queue фіксуються окремо.
- [Ліміти-Codex.ps1](../.Інструменти/Автоматизація/Адаптери/Ліміти-Codex.ps1) — структуровані квоти без сирих відповідей і секретів.
- [Надіслати-Codex.ps1](../.Інструменти/Автоматизація/Адаптери/Надіслати-Codex.ps1) — доставка через codex queue до явно вказаного UUID. Текст екранований як аргумент Windows без shell; не містіть секретів, оскільки аргументи можуть бути видимі локальному власнику процесів. Межа запиту — 24000 символів.

## Використання

Потрібні Windows PowerShell 5.1, WPF та codex.exe у доступному PATH з уже налаштованою авторизацією. Для запуску відкрийте .Інструменти/Автоматизація/Показати таймери.cmd. Він задає RemoteSigned лише дочірньому процесу PowerShell, не змінює постійної чи глобальної execution policy. Суворіші групові правила продовжують діяти; за їх блокування потрібне штатне схвалення/підписування. Українські .ps1/.psm1 збережені як UTF-8 BOM для Windows PowerShell 5.1.

1. У цільовому чаті Codex виконайте /status й скопіюйте UUID сеансу. Укажіть його у вікні; інструмент не переглядає сховище сеансів.
2. «Новий запит» зберігає попередню непорожню чернетку та очищає поле. Напишіть власний текст і натисніть «Зберегти запит» або зачекайте автозбереження. Виберіть попередній текст зі списку; фільтр «лише надіслані» показує всі збережені прийняті queue запити. Поле не обрізає багаторядковий текст при повторному виборі.
3. Для ручного таймера введіть ГГ:ХХ (01:30) або хвилини (90) й натисніть «Ручний таймер». Межі: 1 хвилина — 7 днів. Увімкніть надсилання, якщо потрібно передати запит після відліку; без нього це нагадування. Ручне поле не змінює автоматичний цикл.
4. «Увімкнути автоматичний цикл · 05:05» вмикає надсилання та повтор з фіксованим інтервалом 305 хвилин. Позначка «Я за ПК» зберігається, а не скидається приховано. Щоб дозволити автоматичний розгляд без автора, зніміть її явно.
5. «Таймер до відновлення» чекає останнього обмежувального вікна плюс 5 хвилин; потім квоти перечитуються. «Перевірити квоти» лише читає дані, не запускає роботу.
6. «Зупинити» скасовує очікування, а не вже прийнятий запит. Повтор рахується від прийняття queue, не від завершення роботи агента. Чергове повідомлення не є дозволом запускати незалежну паралельну сесію.

Історія приватна, ігнорується Git; секретів у запиті бути не повинно. Після додавання службової політики довжина перевіряється повторно, щоб не перевищити обмеження командного рядка.

Закриття вікна скасовує очікування. Після перезапуску автоматичні запити не відновлюються самі. Під час доставки queue закриття блокується до відповіді процесу, щоб не вдавати відкликання запиту. Вимкнення автоматики запобігає наступному повтору.

## Квоти й обмеження

Офіційні [команди Codex](https://learn.chatgpt.com/docs/developer-commands?surface=cli) визначають /status як інтерактивний перегляд стану. Для машинного читання [App Server](https://learn.chatgpt.com/docs/app-server) надає account/rateLimits/read після initialize/initialized. Адаптер бере лише тривалість вікна, залишок та UTC відновлення, не читає файлів авторизації.

Політика цього проєкту: залишок 300 хв ≤10% або 10080 хв ≤5% блокує автоматичну роботу. Невідомі/непідтримані вікна також зупиняють надсилання до адаптації. Час таймера не доводить наявності квоти. Після невизначеної помилки повтор вимкнений: запит уже міг бути прийнятий, тому спочатку перевірте сеанс.

Команда queue підтверджена локальною довідкою codex queue --help і використана в робочих авторських прикладах; потрібен працездатний локальний сервіс доставки та відповідна розмова. Якщо версія CLI не підтримує queue, адаптер зупиняється без переходу до незалежного exec. При зміні .Налаштування під час очікування планувальник зупиняє автоматику для повторного перегляду. Ручна перевірка квот не активує запиту.

Відмінність нового прикладу від авторського: тут один таймер, редагований запит та історія у вікні, перевірка квот перед доставкою; в авторському комплекті два таймери й Task Scheduler, які переживають закриття монітора. Для такого фонового режиму використовуйте його інструкцію адаптації; у цій ітерації завдання Windows не реєструються. Нова реалізація не оголошується перевіреним замінником усіх функцій оригіналу.

Читання квот виконане 2026-10-19 о 02:14 за Києвом: канал повернув відомі вікна 300/10080 хв, залишки 79%/97%. Це знімок на момент перевірки, не поточна гарантія. GUI, повтор та реальне надсилання ще не перевірені в роботі. Синтаксичний розбір не є доказом інтеграції. У цій ітерації планувальник не активується автоматично й ПК не вимикається.

## Схвалення у v0.4.0

Типово «Я за ПК» ввімкнено: наступна доставка запитує user/on-request/workspace-write, рішення приймає автор. Якщо надсилання увімкнено й автор явно зняв присутність, доставка запитує approve-for-me. [OpenAI описує цей режим](https://learn.chatgpt.com/docs/permission-modes) як автоматичний розгляд запитів без скасування sandbox; відмова рецензента не обходиться.

Перемикач впливає на наступну доставку, не відкликає вже прийняті запити та не змінює непомітно поточний чат. Повернувшись під час роботи агента, оберіть Ask for approval у меню дозволів чату для негайного ручного контролю. Застосування параметрів до живого сеансу залежить від підтримки CLI/клієнта; наскрізна перевірка ще потрібна.

Службова політика додається до кожного відкладеного повідомлення модулем Політика-запиту.psm1. Вона вимагає оцінки необхідності, меж доручення, оборотності й ризику, а також журналювання кожного запиту. Повний текст користувача зберігається окремо, без змішування зі службовою обгорткою.

«Журнал схвалень» показує останні 300 подій з .Стан/Автоматизація/Схвалення.jsonl; сам журнал не обрізається. Планувальник автоматично фіксує спробу, режим і результат доставки. Агент записує оцінку, доступне фактичне approved/denied та executed/failed через Записати-рішення.ps1 з тим самим RequestId. Джерела user/auto_review відокремлені від agent/scheduler; останні не можуть записати власну оцінку як схвалення.

Приклад форми виклику адаптера журналу (значення ID задає фактичний запит, не копіюйте як реальний доказ):

```powershell
& '.Інструменти/Автоматизація/Записати-рішення.ps1' -RequestId 'REQ-APPROVAL-001' -SessionId $sessionId -Mode automatic -Decision assessed -Source agent -Action 'Несекретний опис потрібної операції' -Reason 'Потреба, межі та оцінка ризику'
```

Це агентський журнал, не перехоплювач усіх внутрішніх подій платформи та не криптографічний доказ рішень. Невідоме рішення не позначається approved. Недоступний журнал зупиняє залежну автономну дію. Нова автоматика не дає дозволу на секрети, непогоджені тести, руйнування або вимкнення ПК.
