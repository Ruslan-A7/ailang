# Синтаксис і сприйняття

Ідея: приймати природну мову та Markdown без втрати обов'язкових вимог.

Версія: 0.6.2.

**AILang постачається у .md. Файли джерела — .ail або .ail.md, допускається змішування; рекомендоване .ail. Кожен Markdown/AILang-файл має один H1 та ідею після нього**, без обов'язкового підпису «Ідея». Файл тільки з ідеєю прийнятний; агент уточнює деталі.

Початковий коментар атрибуції, коли потрібен, передує видимому H1. **В інших форматах результату використовуй коректний рідний синтаксис**, без нав'язування Markdown чи невалідних коментарів.

Рекомендації:
- Одна сутність/клас — окремий файл; споріднене й великі блоки — інтуїтивні папки/підпапки.
- Розділяй блоки/функції лініями між ними, без порожніх роздільників на початку/кінці.
- Змінні/властивості — маркованими списками, пояснення й вимоги — поряд у дужках.
- Функції/методи — нумерованими списками з деталізацією всередині. **Нумерація не задає порядок виконання:** агент визначає виклики за семантикою та залежностями.
- Основні залежності бажано перелічити на початку/в кінці. **Агент визначає їх і без переліку.**
- **Імена файлів/папок мають бути короткими й зрозумілими.** Велика літера рекомендована для файлів/папок/функцій/методів, мала для змінних/властивостей; ураховуй домовленості цільового стеку.

**Жирний текст є обов'язковою вимогою у самій мові й описах автора.** Рекомендації, позначені як рекомендації, не перетворюй на сувору граматику; суперечність між виділенням і модальністю уточни. Приклади пояснюють правила й не додають непов'язаних можливостей продукту.

**Не нав'язуй парадигму програмування.** Процедурні, ООП, функціональні й змішані стилі допустимі навіть усередині файла. Чим докладніший опис, тим точніше слід його реалізувати; гнучкість не дозволяє пропускати вимоги.
