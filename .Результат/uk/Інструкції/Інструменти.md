# Сумісність допоміжних інструментів

Ідея: локалізовані скрипти повинні працювати з фактичним рушієм, файловими шляхами та способом запуску користувача.

Версія: 0.6.4.

**Перед створенням допоміжного скрипта визнач ОС, оболонку, її версію, спосіб запуску, кодування джерела/даних і потрібні переноси рядків.** Не вважай синтаксичну коректність або підтримку Unicode в редакторі доказом запуску в цільовій оболонці.

**Зберігай локалізацію проєкту та працездатність Unicode-шляхів.** Не перейменовуй усі системні папки англійською, щоб приховати проблему. Якщо конкретний запускатор ненадійно обробляє локалізовані команди, дозволений мінімальний ASCII-вхід, який передає керування Unicode-сумісному рушію; його виняток поясни в документації. Інтерфейс і повідомлення зберігають мови проєкту.

**Для Windows CMD у базовому прикладі використовуй ASCII-команди й CRLF; локалізований код завантажуй через окремий PowerShell-вхід. Для Windows PowerShell 5.1 скрипти/модулі з не-ASCII текстом зберігай UTF-8 BOM.** Для PowerShell 7, POSIX та інших рушіїв обирай сумісне кодування окремо: вимогу BOM/CRLF не переносити універсально. Зокрема, не додавай BOM перед POSIX shebang.

**Указуй кодування під час читання/запису тексту, аргументів і стандартних потоків, де це потрібно.** Налаштування консолі не виправляє автоматично байти файла або протокол дочірнього процесу. Не змінюй глобальну кодову сторінку/профіль/політику заради локального інструмента.

**Правильно передавай аргументи та шляхи з пробілами й Unicode.** Для власних ресурсів використовуй папку скрипта, не випадковий поточний каталог. Не збирай виконуваний shell-код із тексту користувача. Відокремлюй локалізований текст від синтаксичних роздільників: типографські лапки можуть бути помилково сприйняті рушієм як лапки коду.

**Зберігай вимоги кодування й перенесень рядків після Git checkout**, наприклад локальним .gitattributes для відповідних типів файлів. Не перекодовуй авторські матеріали або архіви без дозволу.

**Обробляй помилки до завантаження GUI й імпорту модулів.** При прихованому запуску показуй доступний користувачу діалог або безпечний локальний діагностичний запис; не губи помилку разом із консоллю. Повторний запуск має пояснювати вже відкритий екземпляр.

**Перевіряй доручене виправлення через фактичний спосіб запуску**, коли це дозволено й не має непогоджених побічних дій: для .cmd недостатньо окремо відкрити .ps1. Для локалізованих інструментів ураховуй шляхи з пробілами, наявність вікна та правильність тексту. Запуск діагностики не дозволяє приховано надсилати запити, вмикати цикли, схвалювати операції або вимикати ПК. Тести потребують окремого дозволу за правилами проєкту.

**Звітуй окремо про огляд/синтаксис, створення GUI, фактичний запуск, доставку та виконання.** Успіх одного етапу не доводить решти; підтвердження користувача записуй із версією та перевіреною дією.

## Локальний стан допоміжних інструментів

UUID сеансу, доступна назва чату, шлях до встановленого CLI, історія та журнали мають зберігатися локально в межах поточного проєкту, бути виключеними з Git і не містити секретів. Не змушувати користувача повторно вводити збережений UUID. Назву читати лише підтриманим API без завантаження історії та без запуску нового запиту; її недоступність не робить UUID недійсним. Формат історії має зберігати записи без вкладених службових оболонок; перед міграцією створювати копію, про втрати повідомляти прямо. Помилки квот показувати з конкретною безпечною причиною, не підміняти вигаданими даними.
