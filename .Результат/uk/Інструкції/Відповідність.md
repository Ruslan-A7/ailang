# Вимоги та приймання

Ідея: простежувати задум до результату й фактичної перевірки.

Версія: 0.3.0.

**Вимоги мають стабільні ID**, наприклад REQ-001. Якщо автор їх не вказав, агент призначає ID в плані без редагування захищеного джерела. Уточнення зберігає ID/історію, вилучені ID не перевикористовуються.

**Для кожної вимоги записуй:** джерело (файл/розділ), нормативність, зміст, погоджений критерій приймання, результуючі файли/поведінку, спосіб і фактичний статус перевірки. Статуси: заплановано, реалізовано, перевірено, заблоковано, пропущено через середовище.

Критерій описує спостережувану властивість/поведінку, суттєве невідоме уточнюється. **Наявність критерію не дозволяє запускати тести.** Можливі читання, огляд, синтаксичний аналіз або окремо дозволені тести.

**Під час рефакторингу простежуй ID і граф залежностей**, зберігай критерії без погодженої зміни. Перед завершенням зістав кожен нормативний пункт із результатом; тематична карта не доводить повноти. Не обіцяй 100% тотожності між моделями й не оголошуй готовності при непозначених пропусках.
